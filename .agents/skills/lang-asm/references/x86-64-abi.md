# x86-64 System V AMD64 ABI & Calling Conventions Technical Reference Guide

## 1. Register Roles & Preservation Rules

Under the System V AMD64 ABI standard (used by Linux, macOS, FreeBSD, OpenBSD, Solaris):

| Register | Purpose | Preserved Across Calls? (Callee-Saved) |
| :--- | :--- | :--- |
| `RAX` | 1st return register / syscall number | No (Caller-saved) |
| `RBX` | General purpose / base register | **Yes (Callee-saved)** |
| `RCX` | 4th integer argument / string count | No (Caller-saved) |
| `RDX` | 3rd integer argument / 2nd return | No (Caller-saved) |
| `RSI` | 2nd integer argument / source index | No (Caller-saved) |
| `RDI` | 1st integer argument / destination index | No (Caller-saved) |
| `RBP` | Frame pointer or general purpose | **Yes (Callee-saved)** |
| `RSP` | Stack pointer | **Yes (Callee-saved)** |
| `R8`  | 5th integer argument | No (Caller-saved) |
| `R9`  | 6th integer argument | No (Caller-saved) |
| `R10` | Temporary / static chain pointer | No (Caller-saved) |
| `R11` | Temporary / flags scratch | No (Caller-saved) |
| `R12` | General purpose | **Yes (Callee-saved)** |
| `R13` | General purpose | **Yes (Callee-saved)** |
| `R14` | General purpose | **Yes (Callee-saved)** |
| `R15` | General purpose | **Yes (Callee-saved)** |
| `XMM0`-`XMM7` | Floating-point / SIMD arguments | No (Caller-saved) |
| `XMM8`-`XMM15`| SIMD scratch registers | No (Caller-saved) |

## 2. Stack Frame Layout & 16-Byte Alignment

### 2.1 The Entry Condition
When a caller executes `call target_proc`:
1. The CPU decrements `RSP` by 8 and writes the 64-bit return address onto the stack.
2. At the first instruction of `target_proc`, `RSP` is offset by 8 bytes from a 16-byte boundary:
   $$\text{RSP} \equiv 8 \pmod{16}$$

### 2.2 Re-establishing 16-Byte Alignment
Before `target_proc` executes any subsequent `call`:
- **Pattern A (Standard Frame Pointer)**:
  ```gas
  push rbp               # RSP - 8 => RSP = 0 mod 16
  mov rbp, rsp
  sub rsp, 16            # RSP - 16 => RSP = 0 mod 16 (preserved)
  call child_proc
  leave                  # mov rsp, rbp; pop rbp
  ret
  ```
- **Pattern B (No Frame Pointer, Leaf / Small Function)**:
  ```gas
  sub rsp, 8             # Re-aligns RSP: (8 - 8) = 0 mod 16
  call child_proc
  add rsp, 8
  ret
  ```

## 3. The Red Zone

The System V AMD64 ABI reserves a 128-byte area below `RSP` called the **Red Zone**:
- The Red Zone is guaranteed not to be clobbered by asynchronous kernel signals or interrupt handlers in user space.
- A **leaf function** (one that calls no other functions) may use this 128-byte region without executing `sub rsp, N` or adjusting `RSP`.
- **Warning**: The Red Zone is NOT available in the Microsoft x64 ABI (Windows) or in Linux kernel mode (`-mno-red-zone`).

## 4. DWARF Call Frame Information (CFI) Mechanics

Debuggers and C++ / Rust exception personality routines parse the `.eh_frame` ELF section generated by `.cfi_*` directives:
- `.cfi_startproc`: Emits an entry in `.eh_frame`.
- `.cfi_def_cfa_offset N`: Specifies the current Canonical Frame Address (CFA) offset relative to `RSP`.
- `.cfi_offset reg, -N`: Informs unwinder that register `reg` is saved at `CFA - N`.
- `.cfi_endproc`: Closes the function frame definition.
