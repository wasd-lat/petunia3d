# GitHub Issue Creation Guidelines

## Overview
Creating a well-structured issue is critical for effective project management and swift resolution. Issues serve as the primary unit of work for bugs, feature requests, and tasks.

## Anatomy of a Good Issue
1. **Clear Title**: Summarizes the problem or request in one sentence.
2. **Context**: Explains *why* this issue matters and the current state.
3. **Reproduction Steps**: (For bugs) Exactly how to trigger the problem.
4. **Expected vs. Actual Behavior**: What happened vs. what should have happened.
5. **Environment**: OS, browser, version numbers.
6. **Actionable Acceptance Criteria**: (For features/tasks) What defines "done".

## Labels
Always apply appropriate labels to aid triage:
- `bug`: Something isn't working.
- `enhancement`: New feature or request.
- `documentation`: Improvements or additions to documentation.
- `good first issue`: Good for newcomers.

## Anti-Patterns
- **The "It's broken" issue**: No details, no repro steps.
- **The mega-issue**: Bundling 5 different bugs or features into one issue. Split them up!
