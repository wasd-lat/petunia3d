# Authentication Security Cheat Sheet

Authentication is the process of verifying that an individual, entity, or website is whom it claims to be.

## 1. Password Management
- **Storage**: Never store plaintext passwords. Always salt and hash them using a slow, cryptographic algorithm (Argon2id, bcrypt, PBKDF2).
- **Complexity**: Enforce a minimum password length (e.g., 8-12 characters). Do not force arbitrary complexity rules (like requiring symbols) if the password is long (e.g., passphrases).
- **Pwned Passwords**: Check passwords against lists of known breached passwords (e.g., HaveIBeenPwned API) during registration and password changes.
- **Recovery**: Use secure, time-limited, single-use tokens for password resets. Do not use security questions (they are often public knowledge).

## 2. Multi-Factor Authentication (MFA)
- Strongly encourage or require MFA.
- Support strong factors (FIDO2/WebAuthn, TOTP) over weak factors (SMS, Email) where possible.
- Ensure MFA recovery codes are provided and stored securely.

## 3. Session Management
- **Token Entropy**: Ensure session IDs are at least 128 bits long and generated by a Cryptographically Secure Pseudo-Random Number Generator (CSPRNG).
- **Cookie Attributes**:
  - `Secure`: Cookie is only sent over HTTPS.
  - `HttpOnly`: Cookie cannot be accessed via JavaScript (mitigates XSS).
  - `SameSite=Lax` or `Strict`: Mitigates Cross-Site Request Forgery (CSRF).
- **Timeouts**: Implement absolute timeouts (e.g., 24 hours) and idle timeouts (e.g., 30 minutes).
- **Invalidation**: Invalidate sessions upon logout, password change, or when an account is locked.

## 4. API Authentication (Tokens)
- **JSON Web Tokens (JWT)**:
  - Do not store sensitive data in the payload (it is just Base64 encoded, not encrypted).
  - Always enforce a strong signing algorithm (e.g., RS256 with a strong RSA key, or HS256 with a strong secret).
  - Validate the `iss` (issuer), `aud` (audience), and `exp` (expiration) claims.
  - Ensure the token cannot be used before `nbf` (not before) claim.
- **OAuth 2.0 / OpenID Connect**:
  - Use Authorization Code Flow with PKCE for mobile and single-page applications. Avoid Implicit Flow.
  - Validate state parameters to prevent CSRF.

## 5. Brute Force Protection
- Implement rate limiting (e.g., max 5 login attempts per minute per IP/username).
- Implement account lockout after consecutive failures (e.g., lock for 15 minutes after 10 failed attempts).
- Consider CAPTCHA or progressive delays.
